# Business Requirements & System Design

## Project Overview

### The DriverPass project focused on designing a system for a client, DriverPass, a company looking to improve how students prepare for their driving tests. The client identified a problem where many students were failing DMV exams due to a lack of effective preparation tools and resources. To address this, they wanted a system that combined online practice tests with the ability to schedule and manage in-person driving lessons.

### For this project, I developed two key deliverables: a business requirements document and a system design document. These documents outline the system’s purpose, functionality, and technical structure, including UML diagrams such as use case, activity, sequence, and class diagrams. Together, they demonstrate how the system meets the needs of both students and staff while improving the overall learning and scheduling experience.



## What I Did Well

#### One of the strongest parts of my work was translating the client’s needs into clear system functionality. I was able to identify key system features such as scheduling driving lessons, tracking test progress, and managing user roles. I also created multiple UML diagrams that clearly represent how the system operates, including user interactions and system processes.

### Additionally, I focused on keeping my designs organized and easy to understand. This was especially important when creating diagrams, where clarity and structure make a big difference. By refining my diagrams and improving their layout, I was able to present a system design that is both accurate and readable.



## What I Would Improve

### If I could revise one part of my work, I would improve the initial version of my class diagram. While the structure and classes were mostly correct, I initially struggled with properly representing relationships and multiplicities between classes. If I were to revise it, I would spend more time ensuring that all relationships clearly reflect real-world interactions and follow UML standards from the beginning.

### This experience helped me better understand how important it is to not only identify system components, but also accurately represent how they relate to each other.



## Interpreting User Needs

### To design the DriverPass system, I carefully analyzed the client interview transcript and identified the needs of different users, including students, instructors, administrators, and the system owner. I then translated those needs into system features such as account management, lesson scheduling, test tracking, and reporting.

### Considering user needs is critical in system design because the system must be practical and usable for the people who interact with it. If user needs are misunderstood or ignored, the system may not solve the original problem. By focusing on user roles and their specific responsibilities, I was able to design a system that supports real-world usage and improves the overall experience.



## My Approach to Software Design

### When designing software, I focus on understanding the problem first before thinking about the solution. I start by identifying the users, their goals, and the tasks they need to complete. From there, I break the system down into smaller components and use diagrams to visualize how everything fits together.

### In the future, I plan to continue using techniques such as UML diagrams, requirement analysis, and iterative design to improve my work. I also see the value in gathering feedback early and refining designs over time. This approach helps ensure that the final system is both functional and adaptable to changing needs.



## Final thought

### This project helped me build a strong foundation in system analysis and design. It also improved my ability to think critically about user needs and translate them into technical solutions. These are skills I plan to continue developing as I grow in software engineering.
