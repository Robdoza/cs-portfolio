CS 305 Software Security Portfolio Reflection

Artemis Financial Software Security Project

Artemis Financial is a financial services company that needed to improve the security of its web application. The client’s goal was to strengthen secure communications, protect customer data during transmission, and verify data integrity. To accomplish this, I performed a vulnerability assessment, refactored the application to use HTTPS with SSL/TLS, implemented SHA-256 checksum verification, and evaluated the project using OWASP Dependency-Check to identify known vulnerabilities in third-party libraries.

One of my greatest strengths during this project was systematically identifying security risks and implementing solutions that followed secure coding practices. Rather than only making the application function correctly, I focused on protecting sensitive information through encryption, certificate-based authentication, and cryptographic hashing. Coding securely is important because software vulnerabilities can expose confidential data, damage customer trust, and create financial and legal risks for an organization. Applying secure development practices improves the reliability, maintainability, and long-term security of software systems.

The most challenging part of the project was configuring and running OWASP Dependency-Check. The initial vulnerability database updates frequently timed out or failed because of network and API limitations. Troubleshooting those issues helped me better understand how modern security scanning tools operate, how vulnerability databases are maintained, and how to configure the tool to complete a successful analysis.

I increased the application’s security by enabling HTTPS with a self-signed SSL certificate, implementing SHA-256 checksum verification to validate data integrity, and performing dependency scanning to identify vulnerable third-party libraries. In future projects, I would continue using tools such as OWASP Dependency-Check, static analysis tools, and manual code reviews alongside secure coding standards to identify vulnerabilities and determine appropriate mitigation techniques.

To ensure the application remained functional after refactoring, I tested the application locally to verify that the HTTPS endpoint and checksum functionality executed without errors. I also performed a secondary dependency scan after completing the refactoring to verify that the new code did not introduce additional security vulnerabilities. Combining functional testing with static security analysis provided confidence that both functionality and security requirements were satisfied.

Throughout this project I used Java, Spring Boot, Maven, Java Keytool, SHA-256 hashing through Java’s MessageDigest class, SSL/TLS certificates, OWASP Dependency-Check, Eclipse IDE, and GitHub. I also applied secure coding principles such as using established cryptographic libraries, avoiding custom security implementations, validating application behavior through testing, and reviewing dependency vulnerabilities before deployment. These tools and practices will continue to be valuable in future software development projects.

If I were presenting this project to future employers, I would showcase both the completed vulnerability assessment report and the secure software implementation. These artifacts demonstrate my ability to analyze software for security risks, implement secure communication using HTTPS and SSL/TLS, apply cryptographic hashing for data integrity, perform dependency vulnerability analysis, troubleshoot security tooling, and verify that software remains functional after security enhancements. Together, they highlight practical experience with secure software development practices that are directly applicable to professional software engineering roles.
